# 工具安全

## 基本原则

- 执行外部 CLI 前，必须确认其对文件系统、网络、进程、系统配置或项目状态的影响。
- 优先使用只读命令、预览模式、dry-run 或明确不会写入的参数。
- 命令应尽量非交互，避免启动需要用户手动退出的界面。
- 不确定工具行为时，先查项目文档、官方文档或使用帮助命令，不要凭记忆猜参数。
- 不得为了省事使用高风险命令绕过项目既有脚本、验证流程或安全约束。

## CLI 与脚本

- 不在项目根目录执行可能生成非规范文件或目录的命令。
- 避免编写一次性脚本；确需编写时，必须说明用途、影响范围和清理方式。
- 临时脚本应优先放在临时目录，或遵循项目已有脚本目录约定。
- 执行脚本前，必须确认脚本会读取、写入、删除或上传哪些内容。
- 不得运行来源不明、内容未审查或会下载执行远程代码的脚本。

## 文件系统影响

- 涉及创建、修改、覆盖、批量编辑文件时，必须遵循 `file-write-safety.md`。
- 涉及删除文件、移动目录、批量重命名或覆盖未提交修改时，必须先列出目标并等待用户确认。
- 破坏性命令必须优先使用 dry-run、预览模式或只读命令。
- 不得静默清理、格式化、重排或批量改写用户未要求处理的文件。

## 进程与服务

- 启动服务前，应先检查项目已有启动脚本、端口约定和当前进程状态。
- 不得无条件启动多个重复服务。
- 终止进程前，必须说明目标进程、端口、用途和终止原因。
- 不得终止与当前任务无关的用户进程。
- 无法确认进程归属时，不得强行终止。

## 系统配置与权限

- 修改系统配置、环境变量、全局工具链或 shell 配置前，必须说明原因、影响范围和回滚方式。
- 需要管理员权限、全局安装或系统级变更时，必须等待用户明确确认。
- 不得擅自安装全局依赖、切换运行时版本或修改系统代理、证书、PATH 等配置。
- 能使用项目局部工具、临时环境或 sandbox 时，不使用系统级变更。

## 网络与外部服务

- 会访问网络、上传文件、调用外部 API 或产生费用的命令，必须先说明用途和风险。
- 真实付费请求必须等待用户明确确认，优先使用 mock、dry-run、sandbox 或测试环境。
- 不得把密钥、token、账号凭据、私有文件或敏感日志上传到外部服务。
