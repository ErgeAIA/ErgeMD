# ErgeMD 项目开发经验档案

> 会话日期：2026-04-30
> 技术栈：React 19 + TypeScript + Vite（前端）；Tauri 2 + Rust + SQLite（后端）；react-markdown + remark-gfm + mermaid 11.14.0
> 任务目标：收尾阶段 Bug 修复——details 折叠失效、Tab 右键功能无效等问题

---

## 1. 最终技术选型

| 维度 | 选型 | 关键理由 | 被否决的替代方案及原因 |
| ---- | ---- | -------- | ---------------------- |
| Markdown 大文件渲染 | 基于块的虚拟化（≥500 行） | 完整 DOM 渲染导致性能问题 | 继续完整渲染（不可行） |
| Mermaid 版本 | 11.14.0 | 支持正式版 xychart（非 beta） | 11.4.1（不支持 xychart-beta） |
| details/summary 原生功能 | 移除自定义组件，使用原生 HTML | 自定义组件破坏折叠行为 | 继续用自定义组件覆盖（已失败） |
| "在资源管理器中显示" | Rust `std::process::Command` 调用系统命令 | Tauri 前端无法直接调用系统级操作 | 前端 `invoke` 调用（不可行） |

## 2. 核心架构决策

- **决策点**：HTML 块解析必须跟踪标签闭合状态
  - **选择**：解析时记录当前标签栈，遇到开始标签压栈，遇到结束标签弹栈
  - **理由**：空行不是 HTML 块的可靠分隔符，嵌套标签会被错误分割
  - **代价/约束**：自闭合标签（br、hr、img）需特殊处理

- **决策点**：表格对齐通过 `align` 属性而非 `style.textAlign`
  - **选择**：从 `props.align` 或 `props.node?.properties?.align` 读取
  - **理由**：remark-gfm 通过 HTML `align` 属性传递对齐信息
  - **代价/约束**：需类型断言 `as any`，因为 React 类型定义中 `align` 不在标准 HTMLAttributes 中

- **决策点**：Tab 右键功能通过 Rust 命令实现
  - **选择**：Rust 后端注册 `reveal_in_explorer` 命令，前端通过 `invoke` 调用
  - **理由**：Windows `explorer /select,` 是系统级命令，必须在后端执行
  - **代价/约束**：跨平台需条件编译（Windows 用 explorer，Unix 用 xdg-open）

## 3. 关键代码模式（可复用片段）

### 3.1 HTML 嵌套标签块解析

**适用场景**：Markdown/HTML 解析器需完整保留嵌套标签结构（如 details/summary、table 系列）

```typescript
function isHtmlBlockStart(line: string): { isStart: boolean; tagName: string | null } {
  const match = /^<([a-z][a-z0-9-]*)\b/i.exec(line.trim());
  return match ? { isStart: true, tagName: match[1].toLowerCase() } : { isStart: false, tagName: null };
}

function isHtmlBlockEnd(line: string, tagName: string): boolean {
  return new RegExp(`</${tagName}\\s*>`, "i").test(line.trim());
}

// 使用
const { isStart, tagName } = isHtmlBlockStart(rawLine);
if (isStart && tagName) {
  const lines: string[] = [rawLine];
  while (i < lines.length) {
    const next = lines[++i];
    lines.push(next);
    if (isHtmlBlockEnd(next, tagName)) break;
  }
  // 整个 <tagName>...</tagName> 块已收集完毕
}
```

**注意事项**：自闭合标签（br、hr、img 等）需额外判断 `/\/>$/.test()` 防止死循环。

### 3.2 ReactMarkdown 自定义组件样式合并

**适用场景**：自定义 ReactMarkdown 组件时保留 remark-gfm 传入的原始属性（如 align）

```typescript
th(props: React.HTMLAttributes<HTMLTableCellElement>) {
  const { children, style, ...rest } = props;
  const anyProps = props as any;
  const align = anyProps.align || anyProps.node?.properties?.align;
  const incomingStyle = style as React.CSSProperties | undefined;

  return (
    <th
      {...anyProps}
      style={{
        padding: "0.6em 1em",
        fontWeight: 600,
        color: "var(--text-heading)",
        ...incomingStyle,
        textAlign: incomingStyle?.textAlign || align,
      }}
    >
      {children}
    </th>
  );
}
```

**注意事项**：用户样式必须放在默认样式之后；align 属性需类型断言读取。

### 3.3 Tauri Rust 系统命令

**适用场景**：前端需调用系统级操作（打开文件管理器、启动外部程序）

```rust
use std::process::Command;

#[tauri::command]
pub async fn reveal_in_explorer(file_path: String) -> Result<(), String> {
    let path = std::path::PathBuf::from(&file_path);
    if !path.exists() {
        return Err("File does not exist".to_string());
    }

    #[cfg(target_os = "windows")]
    {
        Command::new("explorer")
            .args(["/select,", &file_path])
            .spawn()
            .map_err(|e| format!("Failed: {}", e))?;
    }

    #[cfg(not(target_os = "windows"))]
    {
        Command::new("xdg-open")
            .arg(path.parent().unwrap_or(&path))
            .spawn()
            .map_err(|e| format!("Failed: {}", e))?;
    }

    Ok(())
}
```

**注意事项**：Rust 命令需在 `lib.rs` 的 `invoke_handler` 中注册；Windows 路径传递给 explorer 时不要额外引号。

## 4. 踩坑记录（最高价值区）

### 坑 1：HTML 块解析导致 details/summary 折叠失效

- **现象**：点击 `<details>/<summary>` 无反应，始终展开
- **根因**：`markdownBlocks.ts` 解析 HTML 块时，遇到开始标签后只继续收集到空行，导致 `</details>` 被当作新块处理，DOM 结构断裂
- **解法**：用正则匹配标签名，开始标签压栈，遇到对应结束标签才算块结束
- **预防**：所有嵌套型 HTML 标签（table 系、details 系）都需跟踪闭合标签，不能用空行作为分割依据

### 坑 2：自定义 details/summary 组件破坏原生折叠行为

- **现象**：移除了自定义组件后折叠功能恢复
- **根因**：自定义组件返回 `<details {...rest}>` 时，`rest` 中缺少 React 管理的内部状态（`open` 属性），导致浏览器无法维护展开状态
- **解法**：不自定义 details/summary 组件，使用原生 HTML；样式通过 CSS 文件而非组件覆盖
- **预防**：对于 `<details>`、`<select>` 等有内部状态管理的原生元素，优先使用默认渲染

### 坑 3：表格 align 属性读取不到

- **现象**：`:---:` 语法生成的居中/右对齐无效
- **根因**：remark-gfm 通过 `align` 属性（HTML 特性）而非 `style.textAlign` 传递对齐信息；React 的 `HTMLAttributes<HTMLTableCellElement>` 类型定义中不含 `align`
- **解法**：类型断言 `props as any`，从 `anyProps.align` 或 `anyProps.node?.properties?.align` 读取
- **预防**：处理 remark-gfm/rehype-raw 解析结果时，记住它们用的是 HTML 属性而非 style

### 坑 4：Rust 命令未在 lib.rs 中注册

- **现象**：`invoke("reveal_in_explorer", ...)` 报错 command not found
- **根因**：新命令只在 `commands/mod.rs` 中定义，未加入 `lib.rs` 的 `invoke_handler`
- **解法**：在 `generate_handler!` 数组中添加 `commands::reveal_in_explorer`
- **预防**：每次新增 Rust 命令后，检查是否已在 Tauri 的 invoke_handler 中注册

### 坑 5：未使用变量导致 TypeScript 构建失败

- **现象**：`isHtmlBlock is declared but its value is never read`
- **根因**：重构后旧的 `isHtmlBlock` 函数被替代，但未删除
- **解法**：删除废弃函数
- **预防**：重构时及时清理死代码；TypeScript 严格模式检查能捕获此类问题
