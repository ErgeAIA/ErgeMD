## 1. 最终技术选型

| 维度     | 选型          | 关键理由                           | 被否决的替代方案及原因      |
| -------- | ------------- | ---------------------------------- | --------------------------- |
| 国际化   | react-i18next | 成熟稳定，社区活跃，支持TypeScript | 自定义i18n方案 - 重复造轮子 |
| 状态管理 | Zustand       | 轻量无样板代码，性能优秀           | Redux - 过于重量级          |

## 2. 核心架构决策

- **决策点**：深色/浅色主题的思维导图中心节点配色策略
  - **选择**：深色主题使用深色背景+浅色文字，亮色主题使用浅色背景+深色文字
  - **理由**：确保在任何主题下中心节点都有足够的对比度，文字清晰可读
  - **代价 / 约束**：需要为每个主题单独配置配色方案，增加维护成本

## 3. 关键代码模式（可复用片段）

### 3.1 React Ref 空值检查模式

**适用场景**：检查 React ref 是否有效时

**代码**：
```typescript
// 错误写法
if (!scrollContainerRef) return null;

// 正确写法
if (!scrollContainerRef?.current) return null;
```
**注意事项**：React ref 对象本身永远不为 null，需要检查 `.current` 属性

### 3.2 i18n 翻译键命名规范

**适用场景**：统一翻译键命名，便于维护

**代码**：
```typescript
// 命名格式：组件名.功能.描述
// 示例：
{
  "image": {
    "copyImage": "复制图片",
    "zoomView": "放大查看"
  },
  "toc": {
    "navigation": "目录导航"
  }
}
```
**注意事项**：中英文语言文件结构必须完全一致

## 4. 踩坑记录（最高价值区）

### 坑 1：JSON 文件重复对象键导致解析异常

- **现象**：zh-CN.json 文件中存在两个 "toc" 对象键，导致部分翻译失效
- **根因**：手动编辑 JSON 时误添加了重复的对象块
- **解法**：删除重复的对象键，保留第一个完整定义
- **预防**：编辑 JSON 后使用 `pnpm build` 验证，或使用 JSON 校验工具

### 坑 2：React Ref 检查逻辑错误导致组件不渲染

- **现象**：浮动目录（FloatingTOC）组件始终不显示
- **根因**：检查条件 `if (!scrollContainerRef)` 永远为 false，因为 ref 对象本身不为 null
- **解法**：改为检查 `if (!scrollContainerRef?.current)`
- **预防**：理解 React ref 的工作原理，记住 ref 对象和 ref.current 的区别

### 坑 3：深色主题思维导图中心节点对比度不足

- **现象**：深色主题下中心节点文字看不清，背景色与文字色对比度低
- **根因**：中心节点使用亮色背景配合深色文字，与整体深色主题不协调
- **解法**：深色主题使用深色背景+浅色文字，亮色主题使用浅色背景+深色文字
- **预防**：设计配色时使用对比度检查工具，确保 WCAG 合规

### 坑 4：useTranslation 未导入导致构建失败

- **现象**：构建报错 "Cannot find name 'useTranslation'"
- **根因**：组件使用了 `t()` 函数但未导入 `useTranslation` hook
- **解法**：添加 `import { useTranslation } from "react-i18next"`
- **预防**：使用 TypeScript 严格模式，及时发现未定义的标识符
