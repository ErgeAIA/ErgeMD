## 3. 项目概述

- 项目是什么：ErgeMD，专注于 Markdown 阅读的桌面应用
- 主要用户或使用场景：技术文档阅读者、需要导出 Markdown 为 PDF/DOCX 的用户
- 技术栈：Tauri 2 + React 19 + TypeScript + Rust 后端
- 当前问题：PDF 导出功能长期不稳定，图表渲染失败、样式丢失、多文档导出错误
- 当前目标架构或目标行为：
  - PDF 导出独立管线：从 Markdown 原文直接生成完整 HTML，通过 WebView2 PrintToPdf 生成 PDF
  - 支持带样式/灰度双模式
  - 所有图表（Mermaid、PlantUML）必须在导出前渲染完成
- 明确的非目标：
  - 不追求导出内容完全可编辑（PDF 本质不可编辑）
  - 不追求跨平台统一导出（各平台独立实现）

## 5. 历史事故和硬约束

| 事故 | 症状 | 根因 | 预防规则 |
| ---- | ---- | ---- | -------- |
| PDF 导出图表不渲染 | 导出 PDF 中所有图表空白 | 虚拟滚动卸载不可见 block；mermaid.render() 与主应用冲突；WebView file:// URL 安全策略阻止 | 导出使用独立管线，不复用阅读组件 |
| PDF 多文档导出错误 | 无论打开哪个文档，都导出第一个打开的文档 | `document.querySelector(".markdown-body")` 永远选到第一个 Tab | 必须从 fileStore 获取 currentContent |
| 内联 Markdown 解析错误 | 图片链接语法被错误解析 | 图片正则后于链接正则执行 | 调整解析顺序：图片 → 链接 |
| Obsidian Callout 图标不显示 | 示例文档中 NOTE 提示框图标空白 | 转义语法 `\[!NOTE]` 导致 callout 检测失败 | 检测正则增加对转义写法的兼容 |
| PDF 导出点击无反应 | 点导出后无任何输出 | `forceRenderAllContent` 函数死锁 | 简化状态管理，移除死锁的回调机制 |
