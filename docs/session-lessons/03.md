# ErgeMD 浮动 TOC 交互修复经验档案

> 会话日期：2026-05-02T22:30
> 技术栈：React 19 + TypeScript + Vite 7 + Tailwind CSS v4 + Zustand 5 + Tauri 2 + @tanstack/react-virtual 3
> 任务目标：修复浮动 TOC 交互问题（hover 静默、点击跳转精度、高亮跟随、标题层级支持）

## 1. 最终技术选型

| 维度         | 选型                                                      | 关键理由                                                               | 被否决的替代方案及原因                      |
| ------------ | --------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| 滚轮事件拦截 | 原生 `addEventListener("wheel", ..., { passive: false })` | React `onWheel` + `stopPropagation` 无法阻止原生事件传播到下方滚动容器 | React `onWheel` + `stopPropagation`（无效） |
| 高亮保护机制 | 点击后 500ms 内忽略 scroll 回调                           | 滚动动画触发 scroll 事件会覆盖 `onActiveTocChange` 设置的正确高亮      | 无保护（高亮被覆盖）                        |
| 跳转偏移策略 | 固定 48px 顶部偏移                                        | 避免鼠标上移显示菜单时遮挡跳转后的标题内容                             | 无偏移（内容被菜单遮挡）                    |
| 标题层级支持 | 1-6 级全部支持                                            | 用户反馈 4/5/6 级标题无法跳转                                          | 仅 1-3 级（功能不完整）                     |

## 2. 核心架构决策

- **决策点**：hover TOC 时如何阻止内容区域滚动
  - **选择**：原生 `addEventListener("wheel", ..., { passive: false })` + `stopImmediatePropagation()` + `preventDefault()`
  - **理由**：React 的 `onWheel` 合成事件无法阻止原生事件传播到下方滚动容器
  - **代价 / 约束**：必须使用 `passive: false`，否则 `preventDefault()` 无效

- **决策点**：点击 TOC 后如何保持正确高亮
  - **选择**：点击时通过 `onActiveTocChange` 立即设置高亮，500ms 内忽略 scroll 回调
  - **理由**：滚动动画期间 scroll 事件会根据视口顶部 block 重新计算高亮，覆盖正确值
  - **代价 / 约束**：500ms 内手动滚动不会更新高亮（可接受）

- **决策点**：跳转后如何避免菜单遮挡
  - **选择**：固定 48px 顶部偏移量
  - **理由**：菜单栏高度约 48px，固定偏移简单可靠
  - **代价 / 约束**：硬编码值，若菜单栏高度变化需同步修改

## 3. 关键代码模式（可复用片段）

### 3.1 原生滚轮事件拦截（hover 静默）

**适用场景**：悬浮面板需要独立滚动，同时阻止事件传播到下方滚动容器

**代码**：
```typescript
useEffect(() => {
  const nav = navRef.current;
  if (!nav) return;

  const onWheel = (e: WheelEvent) => {
    if (isHovering) {
      e.stopImmediatePropagation();
      e.preventDefault();
      // 处理面板自身滚动
      setScrollOffset((prev) => {
        const next = prev + e.deltaY;
        return Math.min(Math.max(next, 0), maxScroll);
      });
    }
    // 非 hover 状态：不做任何处理，让事件自然传播
  };

  nav.addEventListener("wheel", onWheel, { passive: false });
  return () => nav.removeEventListener("wheel", onWheel);
}, [isHovering, maxScroll]);
```

**注意事项**：
- 必须使用 `passive: false`，否则 `preventDefault()` 无效
- 使用 `stopImmediatePropagation()` 而非 `stopPropagation()`，确保同元素其他监听器也被阻止
- 非 hover 状态不要调用 `preventDefault()`，让事件自然传播

### 3.2 点击后临时忽略 scroll 回调

**适用场景**：点击导航项触发滚动动画时，防止 scroll 事件覆盖正确的高亮状态

**代码**：
```typescript
const clickTimestampRef = useRef(0);

// 点击时记录时间戳
const handleClick = (index: number) => {
  clickTimestampRef.current = Date.now();
  setActiveIndex(index);
  scrollToItem(index);
};

// scroll 回调中检查时间戳
const onScroll = () => {
  requestAnimationFrame(() => {
    // 点击后 500ms 内忽略 scroll 回调
    if (Date.now() - clickTimestampRef.current < 500) return;
    // 正常更新高亮
    setActiveIndex(calculateActiveIndex());
  });
};
```

**注意事项**：
- 时间窗口需覆盖滚动动画 duration（通常 300-500ms）
- 使用 `requestAnimationFrame` 避免高频 setState

### 3.3 手动计算 scroll 偏移（替代 scrollIntoView）

**适用场景**：需要精确控制滚动目标位置，避免 `scrollIntoView` 滚动所有祖先元素

**代码**：
```typescript
const scrollToElement = (targetEl: HTMLElement, offset: number = 0) => {
  const container = scrollContainerRef.current;
  if (!container) return;
  
  const containerRect = container.getBoundingClientRect();
  const targetRect = targetEl.getBoundingClientRect();
  const targetScrollTop = targetRect.top - containerRect.top + container.scrollTop;
  
  container.scrollTo({
    top: targetScrollTop - offset,
    behavior: "smooth",
  });
};
```

**注意事项**：
- 在包含 `position: fixed` 元素的布局中，禁止使用 `scrollIntoView`
- `offset` 为正数时目标元素会向下偏移

## 4. 踩坑记录（最高价值区）

### 坑 1：React onWheel 无法阻止事件传播到下方滚动容器

- **现象**：hover TOC 面板时滚动鼠标，下方内容区域仍然跟随滚动
- **根因**：React 的 `onWheel` 是合成事件，`stopPropagation()` 只能阻止 React 事件系统内的传播，无法阻止原生事件继续传播到 DOM 树中下方的滚动容器
- **解法**：改用原生 `addEventListener("wheel", ..., { passive: false })` + `stopImmediatePropagation()` + `preventDefault()`
- **预防**：涉及跨容器滚动拦截时，优先使用原生事件监听器

### 坑 2：passive: true 导致 preventDefault() 无效

- **现象**：添加了 `preventDefault()` 但内容区域仍然滚动
- **根因**：`passive: true` 是性能优化提示，告诉浏览器该监听器不会调用 `preventDefault()`，浏览器会立即执行默认滚动行为，导致 `preventDefault()` 被忽略
- **解法**：改为 `passive: false`
- **预防**：需要调用 `preventDefault()` 时必须使用 `passive: false`

### 坑 3：点击 TOC 后高亮变成上方章节

- **现象**：点击第五章，内容正确跳转，但 TOC 高亮变成 3.2 对齐表格
- **根因**：点击触发滚动动画 → 滚动动画触发 scroll 事件 → scroll 回调根据视口顶部 block 重新计算高亮 → 覆盖了 `onActiveTocChange` 设置的正确高亮
- **解法**：点击时记录时间戳，scroll 回调中检查 `Date.now() - clickTimestamp < 500` 则直接 return
- **预防**：任何由用户交互触发的滚动动画，都需要在动画期间屏蔽 scroll 回调的状态更新

### 坑 4：4/5/6 级标题无法跳转

- **现象**：TOC 显示 4/5/6 级标题，但点击无反应
- **根因**：
  - `toc.ts` 中 ATX 正则 `#{1,3}` 只匹配 1-3 个 `#`
  - `markdownBlocks.ts` 中 `if (level >= 1 && level <= 3)` 过滤了 4-6 级
- **解法**：
  - `toc.ts`：`#{1,3}` → `#{1,6}`
  - `markdownBlocks.ts`：`level <= 3` → `level <= 6`
- **预防**：标题层级过滤条件需与 Markdown 规范（1-6 级）保持一致

### 坑 5：scrollIntoView 在 fixed 布局中导致意外滚动

- **现象**：点击 TOC 跳转后，整个页面布局异常
- **根因**：`scrollIntoView()` 会滚动所有可滚动祖先元素，在包含 `position: fixed` 元素的布局中可能意外影响其他 fixed 元素的位置
- **解法**：改用 `container.scrollTo()` 手动计算目标位置
- **预防**：在复杂布局中避免使用 `scrollIntoView`，改用手动计算
