# Mermaid 11.14.0 图表主题适配开发经验档案

> 会话日期：2026-05-09
> 技术栈：React 19 + TypeScript + Mermaid 11.14.0 + Tauri 2 + Tailwind CSS 4
> 任务目标：修复 Mermaid 高风险图表（Packet/Radar/Treemap）在暗色主题下的可读性，并清理无效 CSS 变量

## 1. 最终技术选型

| 维度 | 选型 | 关键理由 | 被否决的替代方案及原因 |
| ---- | ---- | -------- | ---------------------- |
| Packet 暗色主题 | SVG 后处理注入 scoped CSS | Mermaid 11.14.0 Packet themeVariables 存在 Bug（issue #7058），`packetTextColor` 等变量传入不生效 | 直接使用 themeVariables — Mermaid 内部完全不读取；CSS 全局覆盖 — 会污染其他图表 |
| Radar 曲线颜色 | `cScale0`~`cScale4` themeVariables | Mermaid 11.14.0 仅支持这 5 个变量作为雷达图曲线颜色 | `radarCurve0`~`radarCurve4` — 变量名不被 Mermaid 识别 |
| Treemap 颜色 | classDef important 方式 | Mermaid 11.14.0 不暴露任何 Treemap themeVariables | themeVariables 猜测命名 — 无效 |
| Packet SVG class 注入 | `aria-roledescription="packet"` 检测 + `#<svgId>` 作用域限定 | 避免全局污染，确保 patch 仅影响当前 Packet SVG | 裸 class 选择器 — 会因 SVG 内联 style 优先级失效 |
| Packet SVG class 注入位置 | `</style>` 标签后追加新 `<style>` | 保留原 Mermaid 生成样式，新样式通过 `!important` 覆盖 | 插入到 `<style>` 开头 — 可能被 Mermaid 内部样式覆盖 |

## 2. 核心架构决策

- **决策点**：Mermaid 图表主题适配应采用分层架构（CSS 变量 → Mermaid 适配器 → themeVariables / SVG 后处理）
  - **选择**：三层分离
    1. `core/mermaid/*.css` 定义 `--mermaid-*` CSS 变量，统一引用 `var(--chart-*)`
    2. `MermaidDiagram.tsx` 中 `getMermaidColors()` 读取 CSS 变量
    3. `getMermaidThemeSignature()` 追踪影响渲染的 CSS 变量用于缓存失效
    4. 对于不生效的 themeVariables（Mermaid Bug），使用 SVG 后处理注入 scoped CSS
  - **理由**：14 个主题各自维护一套完整 mermaid 变量导致 328 个重复定义；收敛到适配器层统一管理
  - **代价/约束**：新增图表类型需要同时修改 CSS 适配器和 `MermaidDiagram.tsx`

- **决策点**：Packet SVG patch 使用 SVG 根节点 id 限定选择器作用域
  - **选择**：`#${svgId} .packetBlock { !important }`
  - **理由**：避免全局 `!important` 污染；确保每个 SVG 实例独立
  - **代价/约束**：依赖 Mermaid 生成的 SVG 有稳定 id

- **决策点**：Packet/Radar/Treemap/GitGraph/TreeView 通过不同路径设置颜色
  - **Packet**：SVG 后处理 `patchPacketSvg`（Mermaid Bug 导致 themeVariables 无效）
  - **Radar**：themeVariables `cScale0~cScale4`（唯一有效的 Radar 变量）
  - **Treemap**：classDef important（Mermaid 不暴露 themeVariables）
  - **GitGraph**：CSS 后处理（通用路径）
  - **TreeView**：基础语法 + 无扩展修饰语法

## 3. 关键代码模式（可复用片段）

### 3.1 SVG 后处理 patch 函数模板

**适用场景**：Mermaid 图表 themeVariables 存在 Bug 或不暴露所需变量时，通过 SVG 字符串后处理注入 scoped CSS。

**代码**：

```typescript
function patchPacketSvg(svg: string): string {
  if (!svg.includes('aria-roledescription="packet"')) {
    return svg;
  }
  const idMatch = svg.match(/<svg[^>]*\sid="([^"]+)"/);
  const svgId = idMatch?.[1];
  if (!svgId) return svg;
  const selector = `#${svgId}`;
  const packetPatchStyle = `
<style>
${selector} .packetBlock {
  fill: var(--mermaid-packet-block-bg, var(--bg-tertiary, #262630)) !important;
  stroke: var(--mermaid-packet-block-border, var(--mermaid-edge, #808080)) !important;
}
${selector} .packetLabel {
  fill: var(--mermaid-packet-label-text, var(--text-primary, #E0E0E0)) !important;
}
</style>`;
  return svg.replace("</style>", `</style>${packetPatchStyle}`);
}
```

**注意事项**：
- 必须先检查 `aria-roledescription` 或其他稳定属性确认图表类型
- 使用 `svgId` 限定作用域，不用裸 class 选择器
- 覆盖位置在 `</style>` 后，利用 `!important` 覆盖 Mermaid 内联样式
- patch 后的 svg 必须进入缓存和 `setSvgHtml`

### 3.2 Mermaid 图表类型规范化函数

**适用场景**：图表源码可能包含 frontmatter（`---` 包裹的元数据），需要剥离后再检测类型。

**代码**：

```typescript
function getMermaidSourceForTypeDetection(chart: string): string {
  const trimmed = chart.trim();
  if (!trimmed.startsWith("---")) return chart;
  const endIndex = trimmed.indexOf("\n---", 3);
  if (endIndex === -1) return chart;
  return trimmed.slice(endIndex + 4);
```

### 3.3 ChartColors 接口 + getMermaidColors() 分离模式

**适用场景**：图表颜色配置需要同时支持 themeVariables 注入和 CSS 变量追踪。

```typescript
interface ChartColors {
  packet?: { text: string; };
  radar?: { curve0: string; curve1: string; curve2: string; curve3: string; curve4: string; };
  // 每个图表只保留实际被代码使用的字段，死字段必须及时删除
}

function getMermaidColors(): ChartColors {
  return {
    packet: { text: getCSSVar("--mermaid-packet-text", primaryTextColor) },
    radar: {
      curve0: getCSSVar("--mermaid-radar-curve-0", accentCyan),
      // 只保留 cScale0~cScale4，不猜测 radarBgColor 等无效变量
    },
  };
}
```

**注意事项**：死字段（已删除赋值但留在接口中的字段）必须同步清理，否则 TypeScript 会报错且造成误导

## 4. 踩坑记录（最高价值区）

### 坑 1：Mermaid 11.14.0 Packet themeVariables 存在官方 Bug

- **现象**：暗色主题下 Packet 字段背景仍为 `#efefef` 白色，字段文字为黑色，不可读
- **根因**：Mermaid 内部完全不读取 `packetTextColor`/`packetSlotBgColor`/`packetBorderColor`/`packetDividerColor` 这些 themeVariables（官方 issue #7058）
- **解法**：放弃 themeVariables 方案，改为 SVG 后处理注入 scoped CSS，使用真实 class 名称（`.packetBlock`/`.packetLabel`/`.packetByte`/`.packetTitle`）
- **预防**：对于 Beta/新图表类型，先通过 `mermaid.render()` 输出 SVG 确认真实 class 名称，再决定适配方案

### 坑 2：Radar themeVariables 变量名全部猜错

- **现象**：Radar 图表暗色主题下曲线颜色未变化
- **根因**：15A-R2 阶段猜测的变量名 `radarBgColor`/`radarAxisLabelColor`/`radarCurve0` 等全部不是 Mermaid 11.14.0 支持的变量；实际只有 `cScale0`~`cScale4` 可用
- **解法**：通过 Mermaid 源码分析确认 Radar 仅支持 `cScale0`~`cScale4`，删除所有错误变量赋值
- **预防**：新图表类型的 themeVariables 必须查 Mermaid 官方文档或源码，不要猜测命名

### 坑 3：CSS 选择器猜测导致 Packet patch 完全未命中

- **现象**：15A-R4 注入的 `.packet-slot` / `.packet-slot-text` / `.packet-title` 选择器没有修改任何视觉效果
- **根因**：Mermaid 11.14.0 Packet 的真实 SVG class 是 `.packetBlock`/`.packetLabel`/`.packetByte`/`.packetTitle`，与猜测完全不同
- **解法**：通过 `console.debug` 输出 SVG 内容，确认真实 class 名称后再写选择器
- **预防**：任何 SVG 后处理覆盖必须先打印实际 SVG 内容，确认 class 名后再写 patch 代码

### 坑 4：TreeView 扩展语法不兼容导致 Lexer Error

- **现象**：`Expecting token of type 'STRING2'` 错误
- **根因**：TreeView 示例使用了 `:::highlight`（图标）、`##`（注释）、`icon()`（图标函数）、`trailing slash` 等 Mermaid 11.14.0 TreeView 不支持的扩展语法
- **解法**：最小语法隔离测试，移除所有扩展语法，仅保留双引号字符串的基础节点语法
- **预防**：Beta 图表（`treeview-beta` 等）的扩展语法支持状态不稳定，应使用最简基础语法

### 坑 5：`normalizeChartType` 将 frontmatter 第一行 `---` 误识别为图表类型

- **现象**：包含 frontmatter 的 Mermaid 图表被识别为 `normalizedType: '---'`，导致 themeVariables 设置到错误的图表分支
- **根因**：`normalizeChartType` 直接取首行进行类型检测，未处理 frontmatter
- **解法**：新增 `getMermaidSourceForTypeDetection()` 剥离 frontmatter 后再检测
- **预防**：所有 Mermaid 图表在检测类型前必须先剥离 frontmatter

### 坑 6：14 个主题各自维护一套重复的 `--mermaid-*` 变量

- **现象**：每个主题文件包含 82 个重复的 `--mermaid-*` 硬编码变量定义，总计 328+ 个重复变量
- **根因**：Phase 5 时期将 Mermaid 变量分散到 14 个主题文件中，而非收敛到统一适配器层
- **解法**：将所有 `--mermaid-*` 变量统一收敛到 `core/mermaid/*.css` 适配器文件，主题文件不再重复定义；移除 328 个重复变量
- **预防**：新变量必须放到对应 `core/mermaid/` 适配器文件中，不要散落到各个主题文件

### 坑 7：Packet SVG 后处理 patch 插入位置错误导致不生效

- **现象**：使用 `svg.replace("<style>", "<style>" + newStyle)` 注入后样式不生效
- **根因**：Mermaid 生成的 SVG 中 `<style>` 标签可能包含其他属性如 `<style id="mermaid-something">`，精确匹配 `"<style>"` 不可靠
- **解法**：改用 `svg.replace("</style>", newStyle + "</style>")`，在闭标签前插入新样式
- **预防**：SVG 字符串操作时用闭标签做锚点而非开标签

### 坑 8：Packet patch 使用裸 class 选择器被 SVG 内联 style 覆盖

- **现象**：Packet patch 的 `.packetBlock { fill: ... !important }` 注入后，浏览器 DevTools 显示 `fill` 有删除线（被 SVG 内联样式覆盖）
- **根因**：Mermaid 在 SVG 内联 `style` 属性中设置默认颜色，`!important` 在内联 `style` 属性上不生效（内联样式优先级高于类选择器）
- **解法**：将 patch `<style>` 标签插入到 `</style>` 之后（而非替换），并使用 `#${svgId} .packetBlock` 限定作用域
- **预防**：SVG 后处理 patch 必须追加到 `</style>` 之后，且用 id 限定作用域

## 5. 验证过的操作清单（Checklist）

下次遇到 Mermaid 新图表类型主题适配，按顺序执行：

- [ ] 1. 查 Mermaid 官方文档确认该图表支持的 themeVariables 名称
- [ ] 2. 如文档不完整，查看 `mermaid/src/<chartType>/**` 源码确认 `themeVariables` 字段
- [ ] 3. 运行 `mermaid.render()` 获取实际 SVG，保存到文件确认真实 class 名称
- [ ] 4. 根据以下判断选择适配路径：
    - themeVariables 有效且文档确认 → 直接使用 themeVariables
    - themeVariables 存在 Bug 或不暴露 → SVG 后处理 patch
    - 不支持 themeVariables 但有稳定 class → classDef important 方式
- [ ] 5. 适配完成后在 5 种主题下验证（暗色/赛博朋克/极光/海风/亮色）
- [ ] 6. 检查 `getMermaidThemeSignature()` 是否需要追加 CSS 变量追踪
