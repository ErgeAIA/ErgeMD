## 1. 阶段 0 证据（改前实测）

### 1.1 扫描规模（旧 `scan_workspace`，全量递归 + 整包 IPC）

| 合成 vault | 墙钟 | 单次 payload |
| --- | --- | --- |
| 500 文件 / 10 目录 | 16–17 ms | 79.7 KiB |
| 5,000 文件 / 50 目录 | 113–124 ms | 783.4 KiB |
| 20,000 文件 / 40 目录 | 401–623 ms | 3,013.3 KiB |
| 50,000 文件 / 100 目录 | 1.31 s | 7,533.0 KiB |

结论：20k 档已越过 AGENTS.md「单次 IPC ≤1000 条」；50k 档 7.5 MiB 单包，前端要一次性收下并渲染。

### 1.2 失败语料（逐条实测）

| 语料 | 实测结果（改前） |
| --- | --- |
| 权限拒绝子目录 | **静默当作空目录**——`canonicalize()` 失败使递归短路，用户看到「空文件夹」而非错误 |
| junction 指向祖先（环） | 1 ms 内结束、深度 3；环被 `visited` 集合挡住 |
| >260 字符长路径 | Rust std 自动处理，创建与扫描均正常（22 层） |
| 中文 / 数字文件名 | 纯字典序：`第10章` 排在 `第1章` 前 |
| 外部新建 / 改名 / 删除 | 树**永不更新**，只能重启（源码无 watcher、无刷新路径） |
| 扫描中目录被删（代码推演） | 子目录 `read_dir` 出错会经 `?` 冒泡 → 整树失败（未稳定复现，按代码路径判定） |

勘误：动手前曾判断「权限目录导致整树失败」，实测推翻——真实行为是静默丢失，更难发现。

### 1.3 参照行为差分（只读官方文档）

| 行为 | 改前 ErgeMD | Obsidian / VS Code | 本批处置 |

| 树内筛选 | 无 | VS Code Ctrl+Alt+F，支持高亮/过滤与模糊 | 已做：文件名搜索（后端，200 上限）+ 扁平结果 |

| 键盘 / ARIA | 声称 roving，实际每项 `tabIndex=0`；无父级回退、无 typeahead | 标准树键盘 | 已做：真 roving、`aria-level/setsize/posinset`、← 回父、首字母跳转 |
| 面板语义 | modal：遮罩 + 焦点陷阱 | 非模态侧栏 | 已做：改非模态，与 RightPanel 一致 |

## 2. 阶段 1 设计裁决

### 2.1 状态机

| 状态 | 触发 | UI |
| --- | --- | --- |
| 无工作区 | `workspacePath` 为空 | 面板不挂载 |
| 根层加载 | 首次打开 / 换工作区 | 「正在读取文件夹…」 |
| 就绪 | 根层返回 | 树 |
| 根层失败 | 目录被删 / 不可读 | 「无法读取此文件夹」+ 重试 |
| 目录加载中 | 已展开、尚无结果 | 该目录下「正在读取…」 |
| 目录为空 | 条目为 0 | 「空文件夹」 |
| 目录失败 | 展开读取失败 | 该目录下错误行 + 重试；同级不受影响 |
| 截断 | 单层 >1000 条 | 「条目过多，仅显示前 1000 项」 |
| 层级过深 | 展开深度 ≥32 | 「目录层级过深，已停止展开」 |
| 陈旧 | 外部变更 | 回焦 / 开面板 / 手动刷新时**静默**重扫（不闪骨架） |
| 筛选中 | 输入非空 | 扁平结果（名称 + 相对目录），计数；Enter 打开首个 |

### 2.2 信息架构

- 进面板：懒加载树、文件名筛选、定位当前文件、手动刷新、目录/文件右键、键盘导航、展开状态与宽度记忆。
- 明确不做：创建/重命名/删除/移动、全文搜索、多选、拖拽搬移、书签、按时间排序、全部展开/折叠。
- 理由：阅读器的侧边栏服务「找到并打开」，不是文件管理器；每多一项都要付维护与误操作成本。

### 2.3 模态一致性

裁决：`LeftPanel` 改为非模态 `region`，与已验收的 `RightPanel` 同一模型（无遮罩、无焦点陷阱、Esc / 点击面板外收起、标题栏除外）。
理由：用户已确认「设完/看完直接离开」的操作模型；阅读区必须始终可读可交互。焦点陷阱在侧栏里没有对应的任务闭环，只制造「必须先关面板」。

### 2.4 新鲜度机制（不做 watcher 的理由）

- 机制：窗口 `focus` / `visibilitychange`(visible) / 面板打开 / 手动刷新 → 250ms 防抖 → 重扫根层 + 所有**已展开**目录。延迟 N = 回到窗口即刻（防抖 250ms）。
- 不做 watcher：需新增 Rust 依赖（许可证与编译体积要先评估）；Windows 上网络盘、junction、编辑器原子保存（rename）会让 watcher 实现复杂化；本应用的核心金路径（在外部新增后切回来打开）由回焦刷新已覆盖。
- 已知缺口：窗口保持前台时，外部改动不会自己出现；点一次刷新按钮即可。若后续要求「前台实时」，再评估 `notify`。

## 3. 阶段 2 实现

### Rust（`src-tauri`）

- `scan_directory(dir_path, limit?)` → `DirListing { entries, truncated }`：只读一层；目录在前、文件在后，自然排序（数字段按数值）；隐藏项、`node_modules`、`target` 跳过；链接只跟随文件，目录链接不展开（防环）；单层上限 1000。
- `search_workspace_files(root, query, limit?)`：BFS 文件名子串匹配，深度 ≤32，单目录不可读则跳过，上限 200。
- 删除旧 `scan_workspace` 全量递归实现。
- `tests/sidebar_scan.rs`：5 条回归（自然排序/噪声跳过、截断、搜索、空查询、Windows 权限目录——父层仍可用、展开报错）+ 1 条 ignore 基准。
- 基准（5k vault）：根层 **0.88 ms / 7.0 KiB**；文件名搜索 **6.6 ms**。

### 前端

- `FileList.tsx` 重写为懒加载 + 扁平可见行模型：`listings` 按目录缓存、`expandedPaths` 走 store 持久化；键盘导航在树容器统一处理（不再每个节点挂 `keydown` + 全树 `querySelectorAll`）。
- `LeftPanel.tsx`：非模态、点外收起、Esc、宽度持久化（`ergemd:left-panel-width`）、首次打开才挂载（关闭后保留实例）。
- `fileStore.ts`：删除死状态 `fileTree`；新增 `expandedPaths` + `setExpandedPaths`；persist 版本 2→3，换工作区清空展开。
- `utils/fileTree.ts`：`ancestorDirs` / `parentDir` / `relativeDirLabel` / `buildRows` + 9 条单测。
- `App.tsx`：根层改用 `scan_directory`；删除 `fileTree` 写入；侧边栏打开已删除文件时按「不存在」处理（移除最近项 + 刷新树 + 警告提示）。
- 右键菜单：目录只给复制路径/资源管理器；文件给打开/新窗口/复制路径/资源管理器；删除与「打开」重复的「在新标签页打开」。
- i18n：`files.*` 新增 15 键（中英），空/加载/错误/截断全部本地化。

## 4. 验收清单（UI）

1. 打开一个含多层目录的文件夹 → 面板第一屏立刻出现根层，不卡顿。
2. 展开一个深层目录 → 有「正在读取」过渡；再展开二级、三级正常。
3. 点开一个文件 → 标题栏/状态栏正常；关面板再打开 → 自动展开并滚动到该文件（高亮青色）。
4. 在系统资源管理器里往该文件夹新建一个 `.md` → 切回 ErgeMD → 列表里出现；删掉它 → 切回 → 消失。
5. 点面板外正文 → 面板收起且正文可点可读；再开 → 筛选框为空、展开状态还在。
6. 筛选框输入文件名片段 → 出现扁平结果与计数；Enter 打开首个；Esc 清空。
7. 右键文件 → 「在资源管理器中显示」真的打开资源管理器并选中；右键目录 → 只有复制路径/显示。
8. 键盘：Tab 进树 → ↑↓ 移动、→ 展开、← 折叠/回父、首字母跳转、Enter 打开。
9. 缩放窗口 / 拖宽度到 180 与 480 → 正常；重启应用 → 宽度与展开状态保持。
10. 把某个子目录设为不可读（或用已删除目录的旧列表）→ 该目录显示错误行 + 重试，其他目录不受影响。

## 5. 风险与后续

- 无 watcher：前台静置时外部改动不自动出现（设计取舍，见 2.4）。
- 目录符号链接不展开：若用户用链接把笔记挂进 vault，链接目录不会出现在树里（文件链接可以）。
- 未做全部展开/折叠、时间排序、创建/重命名/删除（非目标）；若日后要「实时监听」，需先评估 `notify` 的许可证与体积。
- 本批改动未发版；与 `fix/missing-recent-file` 的合并顺序由用户决定（两者都改了 `App.tsx` 与 i18n，合并时留意 `reader.fileMissingRemoved` 与右侧面板相关行）。
